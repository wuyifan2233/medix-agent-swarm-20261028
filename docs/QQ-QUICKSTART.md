# main_copy：QQ 机器人使用指南

适用环境：Windows x64。已经在本机完成真实 QQ 私聊问答验证。

这里的“QQ登录”是**登录一个 QQ 账号作为机器人**，不是用 QQ 登录 MediX 网站。网页仍使用 MediX 的手机号账号。

## 1. 准备两个 QQ 账号

- **机器人 QQ（A）**：手机扫码登录 NapCat，由 MediX 使用它收发消息。
- **接收消息的 QQ（B）**：作为 A 的好友，向 A 提问、接收回答和提醒。

A、B 先互加好友。两者不能是同一个账号。登录 MediX 的手机号和这两个 QQ 账号没有必须相同的关系。

**先退出电脑上登录着 A 的 QQ 客户端**，否则扫码时可能提示“当前账号已登录，无法重复登录”。不用卸载电脑版 QQ。

## 2. 拉取最新代码

第一次拉取，打开 PowerShell：

```powershell
git clone --branch main_copy --single-branch https://github.com/wuyifan2233/medix-agent-swarm-20261028.git medix-integration
cd medix-integration
```

已经有项目目录，先进入该目录，再更新：

```powershell
git switch main_copy
git pull --ff-only origin main_copy
```

如果有未提交改动，先保留自己的修改，不要用重置或覆盖的方式强行更新。

## 3. 首次安装项目依赖

项目依赖已经装好的，可以跳过。本机已验证使用 64 位 Python 3.10：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.integration.txt
```

MediX 本身的模型、短信等配置仍按 [团队启动说明](TEAM-VALIDATION.md) 准备。新目录没有别人的网页账号和数据库，需要配置短信并注册自己的 MediX 账号。

**QQ 这一项不用手动安装 Node.js、SnowLuma，不用填写 QQ 的 HTTP/WS 地址或令牌。**

## 4. 启动 QQ 机器人并扫码

在项目根目录运行：

```powershell
.\start_qq.ps1
```

第一次运行会自动下载官方 NapCat 包（约118 MB），校验后准备运行环境、独立账号数据目录和本机令牌。首次需要联网，后续不必重复下载。

浏览器会打开本机的“**MediX QQ 连接**”页面：

1. 等待页面出现二维码，页面每5秒自动刷新。
2. 用手机上登录的 **机器人 QQ（A）** 扫码。
3. 在手机 QQ 上确认登录。
4. 等页面显示 **“QQ 已在线”**。

这个页面是机器人运行环境的扫码页，和 MediX 网站的手机号登录弹窗不是一回事。不要再把同一个 A 账号登录到普通电脑版 QQ。

## 5. 启动 MediX，连接 QQ

新开一个 PowerShell 窗口，进入同一个项目根目录，按团队原有方式启动项目。例如：

```powershell
.\.venv\Scripts\python.exe run_web.py
```

如果团队使用的是离线知识库启动入口，继续使用团队已经配置好的原启动命令，不用为 QQ 更换知识库或数据库。

浏览器打开 `http://127.0.0.1:8765/`，不要直接打开 `web/static/index.html`。

1. 登录自己的 **MediX 手机号账号**。
2. 展开左侧 **“聊天渠道与提醒”**。
3. 切换到 **QQ**，点击 **“连接本机 QQ”**。
4. 显示 **“已连接”**，并显示机器人 A 的账号信息，说明网页已接上 QQ 服务。

如果 MediX 在运行 `start_qq.ps1` 之前就启动了，先重启 MediX，让它读取自动生成的配置。

## 6. 绑定接收消息的好友

1. 在网页的“好友 QQ 号”中填写 **B 的 QQ 号**，点击 **“绑定好友”**。
2. 用 B 打开和机器人 A 的私聊，查看收到的绑定消息。
3. 按消息提示原样回复 `绑定 验证码`，使用收到的真实验证码，不是填写“验证码”三个字。
4. 收到 **“已确认绑定 MediX”**，表示绑定完成。

绑定码5分钟内有效。过期后，在网页重新点击绑定好友。未完成确认前，该好友不能使用当前 MediX 账号的问答和提醒。

## 7. 验证能否正常使用

用 **B 给 A 发消息**，例如：

> 你好，请简单介绍一下你能做什么。

B 收到机器人回复，才算真实问答链路通过。仅看到网页“已连接”，还没有验证完整问答。

需要验证提醒时，在已绑定的 MediX 账号下创建一条发往 QQ 的测试提醒，并确认 B 在约定时间收到。问答成功不代表定时提醒已单独验收。

## 8. 后续重新启动

电脑重启后，再运行 `.\start_qq.ps1`，然后启动 MediX。脚本会尝试恢复本机已登录的机器人账号；提示扫码时重新扫码。必要时在 MediX 网页重新点击连接。

本机配置保存在 `data/napcat/`，不要删除或发给别人。**每台电脑都需要登录自己的机器人 QQ；拉取代码不会同步别人的 QQ 登录状态、好友绑定、MediX 账号或记忆数据。**

## 常见问题

| 现象 | 处理方式 |
|---|---|
| 提示重复登录 | 退出电脑上同一个机器人 QQ，再等待扫码页刷新并重新扫码。 |
| 首次下载失败或很慢 | 使用下面的代理或离线官方包命令。代理端口填写自己电脑的实际端口。 |
| 扫码页还没有二维码 | 等待核心启动，页面会刷新；长时间没有，查看 `data/napcat/runtime.log` 和 `bootstrap.log`。 |
| 3000、3001 或6099端口被占用 | 先检查是不是已有 NapCat、SnowLuma 或其他服务；不要重复启动不同的 QQ 服务，也不要随意结束不认识的进程。 |
| 网页仍显示找不到 SnowLuma | 确认已更新到最新 `main_copy`，并运行过 `start_qq.ps1`，然后重启 MediX；以前手动设置的进程环境变量也可能覆盖自动配置。 |
| 找不到好友 | A、B 先互加好友；网页填写 B，不是机器人 A 的账号。 |
| 提示渠道被其他 MediX 账号连接 | 先用原来连接的 MediX 账号断开，再换账号连接。每台电脑的 QQ 渠道只供一个 MediX 账号使用。 |
| 能绑定但问答没回复 | 先确认绑定码已回复成功、发消息方向是 B→A，再检查 MediX 的模型配置和服务日志；模型配置问题与 QQ 登录问题分开排查。 |

下载时可选用以下方式之一：

```powershell
# 示例代理端口，按自己电脑修改
.\start_qq.ps1 -Proxy http://127.0.0.1:7890

# 使用已下载的官方 Windows.Node 包，脚本仍会校验文件
.\start_qq.ps1 -Archive 'D:\Downloads\NapCat.Shell.Windows.Node.zip'
```

更详细的配置与实现边界见 [QQ-ONEBOT.md](QQ-ONEBOT.md)。排查时可以提供错误文字，但不要发送日志中的令牌、口令或 QQ 会话数据。

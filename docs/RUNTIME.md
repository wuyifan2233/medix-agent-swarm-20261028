# 运行架构与故障排查

返回 [项目 README](../README.md)。本文对应当前 `medix-agent-swarm-check` 副本，不描述未实现的历史会话功能。

## 网页请求怎样处理

```text
浏览器（index.html / style.css / app.js）
  → POST /api/chat：问题、图片、会话 UUID、Mem0 开关
  → 服务端校验请求与图片，加入单工作线程队列
  → 有新图片：通过 LLMClient 调用图文模型读取可见信息
  → MedicalKnowledgeBase 检索本地 Milvus 资料
  → 问题 + 图片读取结果 + 检索片段交给 SwarmCoordinator
  → 路由为单助手或任务分解后的多助手协作
  → 浏览器轮询任务，展示回答、来源和实际工具状态
```

图片读取、知识库检索和助手分析均为实际调用。前端不会用预设答案代替模型返回。示例图片是虚构的测试素材。

### 服务与接口

入口为 [`run_web.py`](../run_web.py)，通过 Uvicorn 启动 [`web/app.py`](../web/app.py)。

- `GET /`：网页。
- `GET /assets/...`：静态文件。
- `GET /api/health`：知识库状态与条目数、模型名、密钥是否配置；不返回密钥。
- `POST /api/chat`：提交 JSON，返回 `202` 和 `job_id`。
- `GET /api/jobs/{job_id}`：查询当前浏览器拥有的任务。

请求以单个工作线程处理，避免同时使用共享知识库。未完成任务达到 6 个时拒绝新请求；单个分析任务的等待上限为 180 秒。页面使用轮询更新阶段，当前没有逐 token 流式输出。

`model_configured=true` 只表示服务端有配置密钥，不代表接口刚刚通过了联网或鉴权测试。`knowledge=ready` 表示知识库初始化完成；`loading` 表示尚在加载。

### 图片和上下文

前端发送图片 data URL；服务端验证真实像素，最多接收 3 张、单张 8 MB、2000 万像素。整体请求体最多 34 MB。处理时校正方向、转为 RGB、缩放到最长边 2048 像素并重新编码 JPEG，不落盘原图。

图片读取文字会并入后续上下文；服务端按浏览器 Cookie 与会话 UUID 隔离上下文。浏览器刷新后会生成新会话 UUID，因此无法恢复旧聊天。服务端内存里暂时仍有旧上下文，不等于用户可以在界面恢复它。

浏览器 Cookie 为 HttpOnly、SameSite=Strict；任务查询校验所属浏览器；POST 校验来源，Host 限制为本地地址。这些措施针对本地开发，不构成公网多用户身份系统。

## Agent、Skills 与检索

[`SwarmCoordinator`](../swarm/swarm_coordinator.py) 持有健康咨询、症状分析和研究 3 个 Worker Agent。LeadAgent 负责协作所需的任务分解和汇总。具体走单 Agent 还是 Swarm 路径，取决于路由结果。

Worker 通过 [`SkillRegistryMixin`](../agents/skill_registry_mixin.py) 从 `.claude/skills/` 自动发现和注册技能。当前有 9 个技能目录：

- `search-knowledge`：医学资料搜索。
- `assess-risk`：风险评估。
- `analyze-symptoms`：症状分析。
- `recommend-lifestyle`：生活方式建议。
- `disease-code`：疾病编码查询。
- `clinical-guideline`：指南类资料查询。
- `deep-research`：搜索与证据综合。
- `search-history`：短期历史查询。
- `search-similar-cases`：长期记忆查询。

注册技能不意味着每次都会调用。网页显示的“几位助手协作”和工具状态来自实际返回结果，不能仅凭复杂提问就假定所有 Worker 都已参与。

网页会先检索本地资料，并筛选相似度至少 0.4 的结果、按原文去重、最多保留 3 个片段；Agent 内仍可自主选择工具。参考卡片表示检索命中，不代表医学审核或网络验证。

### 训练与推理的区别

当前项目没有训练入口、微调脚本或优化器训练循环。本地 SentenceTransformer 调用 `.encode()` 生成文档/问题向量，属于推理；迁移旧 Milvus 数据也不属于训练。不能因为依赖 `torch` 就把它作为训练模块删除。

### 知识库路径

[`runtime_paths.py`](../runtime_paths.py) 根据项目绝对路径生成哈希，默认把向量库放到临时目录下的独立 ASCII 路径。移动项目会改变默认哈希和数据库位置。

需要查看当前路径，可在项目根目录运行：

```powershell
..\.medix-venv\Scripts\python.exe -c "from runtime_paths import DB_PATH; print(DB_PATH)"
```

`MEDIX_DB_PATH` 可覆盖该路径，通常无需设置。`MedicalKnowledgeBase` 初始化统一调用 `knowledge/bootstrap.py`：默认集合为空时自动只读导入旧库，已有非空集合直接使用并保留自定义文档。迁移脚本复用相同逻辑；导入后数量不符、向量维度不符、源文件缺失等情况会明确失败，不把空库报告为成功。不要把源文件当作V3目录，不要在多个进程中同时打开同一目录。

原文 TXT、旧版向量库和当前向量库是不同数据：直接修改 TXT 不会自动更新旧向量或当前索引。新增文档需调用知识库导入能力并规划索引更新；当前迁移脚本只用于恢复附带的原始 180 条向量，不能充当任意增量数据同步脚本。

## 记忆边界

网页每次请求都会创建协调器，并显式传入：

```python
SwarmCoordinator(
    enable_long_term_memory=payload["remember"],
    memory_user_id=memory_user_id,
    persist_session_summaries=False,
)
```

`web/app.py` 自己维护近期消息及图片读取文字，给后续请求提供上下文。原始图片不保存在该上下文中。

网页的 Mem0 用户按浏览器标识隔离；它不是登录账号，也不承诺换浏览器、清理 Cookie 或 Cookie 过期后还能关联之前的摘要。Mem0 云端摘要与本地页面的聊天记录是两套机制。

命令行沿用协调器默认的本地会话总结行为。研究模块另有可选 Qdrant 路径，短期记忆类支持可选 Redis；当前网页不以 Redis、Qdrant 或历史会话持久化作为运行前提，这些独立服务也未完成当前环境验证。

## 常见问题

### 页面提示 ERR_CONNECTION_REFUSED

先重新运行 `start_web.ps1`。检查启动终端是否已经退出，以及服务是否在监听 8765。页面需要服务持续运行，重启电脑后不会自动恢复。

### 页面能打开，但分析失败

查看服务终端或当前启动方式对应的错误日志。网页对外返回通用错误，后台记录异常类型；从终端启动时，错误通常直接显示在终端。

本机排查曾遇到 `APIConnectionError`：受限执行环境拦截了进程的外网连接。此时前端和知识库可以正常加载，但模型请求无法完成。应检查实际运行进程是否有访问配置 API 的权限。

其他可能原因包括模型鉴权失败、额度或限流、模型不支持图片/工具、网络中断和分析超时。先区分这些原因，再调整配置；不需要为此重新训练或删除知识库。

### 侧栏显示知识库准备中

首次导入依赖或加载嵌入模型可能需要等待。确认模型下载或缓存可用。如果启用了 `HF_HUB_OFFLINE=1`，应先确认模型已缓存；否则移除离线限制后重启。

### 数据库被占用或 8765 端口占用

停止原实例再启动新实例。命令行、网页和真实知识库测试可能占用同一 Milvus Lite 数据目录。不要反复启动多个进程，也不要为了释放占用而删除原始数据库。

### 改了 Key 或模型但页面没有变化

配置在服务进程启动时读取，需要重启后端。只刷新网页不会更新后端环境变量。

### 刷新后聊天消失

这是当前实现的限制。没有历史会话列表、IndexedDB 或本地文件聊天恢复。开启 Mem0 也不会自动重建完整会话。

### 资料里有“最新指南”等字样

这是原始文档内容，不是系统对时效性的验证。应核实真实来源及版本，避免直接把文件标题作为权威证据。


## 网页多实例数据库锁修复（2026-10-30）

直接运行 `run_web.py` 默认监听 8744，参数帮助与实际默认值保持一致。网页未指定数据库路径时，使用上述临时 ASCII 目录下的 `web-<端口>-milvus.db`；命令行原有 `milvus_v3.db` 不变。不同端口默认互不争用锁，新目标从原只读旧库迁入现有 180 条记录，不覆盖旧实例数据。`--db-path` 优先于 `MEDIX_DB_PATH`，显式配置路径时仍由用户保证不被其他实例同时打开。

启动时打印实际网址和数据库目录。数据库无法打开时，网页提示可能被其他实例占用，并建议关闭旧实例或使用 `--db-path`。本次在旧 8755 实例仍持有原默认数据库锁时，使用 `run_web.py --port 8767`（无数据库覆盖参数）成功初始化 180 条记录，并通过真实模型通用问题对话；验证报告在 `verification_web_startup.json`。测试服务验证后停止，避免占用用户后续启动端口。

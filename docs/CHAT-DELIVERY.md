# 会话持久化、流式响应与用量统计

分支：`feature/chat-streaming-wallet`，基于 `main_copy`。更新：2026-10-31。

## 启动与配置

安装 `requirements.integration.txt`，配置现有账号/DeepSeek 环境变量，然后运行 `python run_web.py`。启动自动迁移统一业务库到 `20261031_17`；不另启 Redis、不另建业务 SQLite。默认 `.medix-data/app.db`，可用 `MEDIX_DATABASE_URL` / `--data-dir` 覆盖。保持单进程、单 Uvicorn worker；多 worker 调度、任务租约与后台持久队列尚未实现。

DeepSeek 仍使用 `MEDIX_LLM_PROVIDER=deepseek`、`DEEPSEEK_API_KEY` 和 `deepseek-flash`。凭据不进入消息、事件、用量或 Git。本机验收环境是 macOS 15.5 / ARM64 / Python 3.13.9，依赖按集成清单安装；未声称已在 Windows 重跑。

## 会话及图片

侧栏支持最近100个会话列表、新建、切换、重命名、删除；刷新后恢复当前账号上次打开的会话。浏览器 localStorage 只保存当前会话 ID，正文、图片、任务、上下文和用量存于业务库，查询都按服务端 `user.id` 约束。

上传最多3张、每张8 MB、2000万像素。保存的是经原有像素校验、纠正方向、去除元数据、最长边2048像素的 JPEG data URL，随用户消息存入 SQLite；不保存原始二进制文件。历史可显示压缩图片、读取结果，后续问答沿用已保存的图片上下文或已有病例事实。删除会话级联清理其消息、压缩图、推理快照、事件与用量；独立健康档案、病例事实、提醒及 Mem0 摘要有各自生命周期，不随聊天删除。

完整聊天用于展示，不能直接全部灌入模型。模型上下文仍遵循原有近期6条、人物识别、档案/偏好版本、病例修订及记忆撤回规则。明确指向上一张文档的核对可使用独立 document_context，不将通用/虚构图中的数值归为某个人的病史；切换人物、文档或档案/偏好范围仍隔离。网页 AgentLoop 的临时 ShortTermMemory 每轮前后清理，跨请求只有统一业务库中的筛选快照作为依据；内存字典只作该快照缓存。完成回答和下一轮快照同事务提交；取消或失败不提交该轮推理快照。

同一会话只允许一轮 queued/running，避免并发覆盖上下文。相同账号/request_id/内容的重复提交返回原任务，不重复调模型；相同编号但不同内容返回409。重试失败/取消轮次必须使用新的 request_id，并单独产生用量记录。

服务重启后，queued/running 任务标记为 interrupted，并保留已有事件/正文；不会自动重做模型调用。旧版未落盘的聊天不能追溯恢复。

## 流式和停止

创建任务后，网页使用 SSE 接收阶段、模型正文增量、用量和完成事件。每条事件带递增ID；断线按 Last-Event-ID/after 重放，刷新时先加载保存的草稿和游标，再继续接收，不重复执行任务。完成回答仍通过原来的引用核验、约束修复及呈现逻辑替换草稿。草稿明确标识“完成后校验”，不能视为最终医学结论。

LLMClient 的普通调用、工具调用及多Agent汇总均在网页任务上下文中使用 `stream=True`、`stream_options.include_usage=True`；工具名和 JSON 参数按 index 聚合。内部路由、病例提取、图片读取及推理文本不会作为回答增量展示；Worker 正文与最终汇总可以展示草稿。并发Worker按调用ID区分，页面只显示当前草稿，不混合不同流。推理文本只在内存中用于 DeepSeek 工具续传。

证据 direct 模式增量解析完整句子对象、复用原有引用/quote检查后才展示句子；不展示原始 JSON，末尾仍校验完整结构。表达偏好 JSON 整理在后台完成后替换草稿，不向页面暴露中间 JSON。

停止按钮取消实际后台 asyncio Task，取消传播到正在等待的模型/工具协程，并在 finally 关闭上游响应流。排队任务收到取消后不再开始生成。同步检索或已完成的工具副作用无法回滚；取消不是对已产生供应商费用的撤销。网页断开SSE不代表取消，便于刷新后继续。

## 人民币费率与关怀点（2026-10-31更新）

历史列表位于快捷功能下方，仅显示会话名称及悬浮/聚焦出现的更多菜单；重命名和删除使用独立弹窗，没有重复当前标题或会话累计用量。关怀点余额整合在左下角账户区域内，未展开账号菜单时也直接可见，点击余额打开关怀点消耗记录，余额卡片下按每轮对话分页展示扣点概况，展开可看输入/输出 Token、缓存命中、参与助手数、助手调用次数、全部模型请求数及分阶段用量。助手调用仅统计非 stage 的实际回答助手，流程处理计入模型请求。网页回答末尾保留关怀点消耗和具体助手调用次数，不显示人民币费用；微信/QQ仅发送正文，用量在关怀点记录中查看。记录接口 GET /api/wallet/history 复用账号鉴权；已删除对话保留扣点记录但不再有用量明细。

依据 [DeepSeek官方人民币价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)，Flash 闲时每百万Token：缓存命中输入0.02元、未命中输入1元、输出4元；高峰翻倍。高峰为北京时间周一至周五09:00–12:00、14:00–18:00，中国节假日及周末全日闲时。2026年放假日期依据 [国务院通知](https://www.gov.cn/zhengce/content/202511/content_7047090.htm)。请求开始时选择费率并存快照；未知年份高峰窗口暂按高峰保守估算并标记calendar_confirmed=false，发布日历后可通过MEDIX_PRICE_HOLIDAYS补齐。

每账户默认一次性赠送10,000关怀点；1,000点对应1元模型消耗。MEDIX_INITIAL_CARE_POINTS和MEDIX_CARE_POINTS_PER_CNY控制新钱包，已建立钱包保留原赠送额与兑换率，不会因重启或配置变化再次赠送。首次读取/调用时幂等创建钱包；账号由现有require_user获取，客户端不能指定owner或余额。此为本地应用服务额度，已有未支付充值订单预览，尚无充值入账、提现或真实支付接口。

每次上游模型调用先以输入UTF-8字节上界（含图片）、配置输出上限和高峰费率预留额度，再依提供商usage和该次CNY价格快照实际扣除；单位为0.001点，逐调用向上取整。全部阶段均扣费，包括人物判断、OCR校验、病例整理、路由、工具循环、Worker、汇总和偏好整理。输入中的缓存命中部分单独计价，不重复算作未命中。余额不足时不调用模型，返回关怀点不足提示。受管SDK不自动重试；显式重试单独记账。

账本使用同一业务SQLite中的care_wallets/care_ledger（迁移20261031_16），BEGIN IMMEDIATE串行预留/结算，调用ID为唯一键，重复结算不重复扣点。取消/断线后无法取得usage时不猜零消耗、不立即实际扣款，预留额度标为pending待核对；可在钱包中看到待核对金额。明确被接口400/401/403/404/422/429拒绝的请求释放预留，不扣点。取得最终用量后由settle(call_id,cost_cny)完成核对；当前没有自动对接供应商账单核对或管理员充值界面。

关怀点不是现金余额，人民币费用仍是根据已知usage计算的参考值。历史USD估算行保留原审计快照，展示时按调用时间和人民币规则重算参考费用；升级前的历史不追扣赠送额度。删除聊天会删除聊天用量明细，独立扣点账本保留不含问答正文的调用ID/额度/金额，防止删除会话返还额度；注销账号仍级联清理其本地钱包。重启后余额和待核对预留均保留。

独立执行的档案导入不在当前聊天账本内，网页、QQ与微信问答已统一记账；Search/Fetch等额外工具的独立付费接口尚未接入此钱包，不能将其费用冒充Token费用。

## 接口

- `POST /api/chat`：创建持久任务；旧 `GET /api/jobs/{id}` 状态接口继续可用，重启后可读持久记录。
- `GET /api/jobs/{id}/events?after=N`：SSE，支持 Last-Event-ID；长连接重复检查登录会话是否撤销。
- `POST /api/jobs/{id}/cancel`：请求取消，需既有 CSRF 与 JSON 请求头。
- `GET /api/conversations`、`GET/PATCH/DELETE /api/conversations/{id}`：列表、消息、改名、删除。
- `GET /api/conversations/{id}/usage`、`GET /api/usage`：会话/当前账号汇总。

业务接口复用 require_user；所有写请求保持 Origin、X-Medix-Request、application/json 和 CSRF 检查。跨账号记录返回404，不因知道UUID而获得访问权限。

## QQ / 微信统一扣点与充值订单（2026-10-31）

QQ、微信回调现在创建账号所属的持久化任务，经过同一 ChatRuntime / completion / care_wallet 预留与结算。统一使用绑定账号余额；每次上游模型调用均统计，包括人物判断、病例整理、路由、回答、工具循环与汇总。渠道消息ID组合 bot/peer 身份并按账号和渠道生成请求UUID；已有任务重复投递直接复用已存结果，不再调用模型或扣点。渠道对话保存为稳定会话UUID，可在网页历史恢复，旧渠道上下文首次迁入新键后清理旧键。消耗记录标注网页/QQ/微信来源，删除会话后账本仍保留来源。余额不足返回明确关怀点提示；未知用量保留待核对额度。网页回答转发到手机、固定媒体提示、绑定确认、定时提醒投递本身不调用模型，不另扣点。提醒创建时若调用模型，该轮模型消耗正常结算。

充值按用户确认仅实现界面与未支付订单。钱包提供「消耗记录 / 补充关怀点 / 充值订单」页签，档位为¥10/¥30/¥100，点数按该账号钱包既有兑换率生成并随订单保存。默认对应10,000/30,000/100,000点。服务端决定金额和点数，客户端只提交plan_id及请求UUID；订单账号隔离、幂等创建、最多5笔待支付、24小时过期、可取消和分页查看。迁移20261031_17新增care_orders及渠道标记；只有awaiting_payment/cancelled/expired状态，不暴露paid状态、支付回调、充值入账或客户端确认到账接口。无论创建/取消/过期，余额与已消耗账本都不增加或变更。

接口：GET /api/wallet/plans；POST /api/wallet/orders；GET /api/wallet/orders?offset=0；POST /api/wallet/orders/{id}/cancel。写接口复用CSRF/Origin/JSON校验，限制16KB请求体。后续接入真实商户支付需独立实现服务端验签、金额/币种/订单核对、交易号唯一性与原子幂等入账，再开放付款；目前页面明确提示暂不开放在线支付，不展示虚构二维码。

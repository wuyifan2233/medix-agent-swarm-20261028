# 网页长期记忆：Mem0（2026-10-30）

网页由模型自动判断哪些个人健康信息值得长期保存，再通过 Mem0 Platform 云端写入和检索。亲友分组、来源卡片、原文弹窗、重点高亮、排除关联、停用与删除均保留。网页无记忆开关，保存结果与跳过原因均可查看。

## 配置与启动

在项目 `config.py` 填写 `LOCAL_MEM0_API_KEY` 或通过环境配置 `MEM0_API_KEY`，重启服务。网页通过已安装的 httpx 调用官方 REST API，不依赖旧版 `mem0ai==0.1.0` SDK。命令行原有 LongTermMemory 接口仍保留。

```sh
.venv/bin/python run_web.py --port 8766 --db-path .medix-data/demo-milvus.db
```

健康接口的 `memory_backend=mem0`，`memory_configured` 仅表示有服务端密钥；真实写入、检索和管理的失败会单独反馈，不把存在密钥当作云端成功证明。

## 原文与人物隔离

- WebMem0Memory (`memory/web_mem0.py`) 负责网页云端操作。每个浏览器身份下的本人、父亲、母亲分别使用独立 Mem0 user_id 命名空间。检索与列表都指定范围，并再次验证返回记录的归属；管理操作先核对记录归属。
- 使用 `infer=false` 保存原始用户描述；元数据保留人物、来源会话、原文、图片读取文字、主题、时间和有效状态。这样 Mem0 推断或改写不会破坏原文来源。助手观点、知识库文本、内部子任务不写入用户病史；原始上传图片未保存。
- 新记录由 Mem0 写入并回读核对后才显示「已保存到 Mem0」。异步写入未完成、鉴权失败、限流或网络错误均明确反馈；不静默降级为本机成功。远程操作在线程中运行，不在异步事件循环里同步等待。
- Mem0 语义检索提供候选，再核对人物、会话、有效状态、排除信息与临床主题，最多展示三条。当前仍有主题词及别名门槛，不能把同主题直接判为同一次病程。
- 浏览器身份来自 HttpOnly cookie，有效期一年。尚无登录账户体系或跨设备身份同步；清除 cookie 后不能通过原身份找回记录。

## 本机旧记录与演示

之前 `.medix-data/cases.sqlite3` 中的记录原样保留，不自动上传或删除。管理列表合并显示并标记「本机旧记录（未上传）」，旧记录仍可在云端检索成功后作为明确标记的补充来源。它们的 ID 带 `local:` 前缀，管理操作只作用于本机；Mem0 记录使用真实云端 UUID。旧版 CLI 使用过的共享云端记忆不自动导入当前网页人物命名空间。

「体验记忆新功能」仍是独立的本机虚构演示，回答明确标注为预置文案，不调用 Mem0，也不表示实际云端验证。

## 查看和纠正

- 「我的健康记忆」展示本人；「亲友健康记忆」展示父亲和母亲。其他亲友暂不自动保存。列表显示最近 100 条，包含停用记录。
- Mem0 来源卡片明确标记「Mem0 云端」，保留原文日期、人物与关联原因。只有模型输出了有效来源编号时标记「本次回答参考」；没有编号时说明「回答未标注来源编号」。这不等于验证模型逐句使用了每段证据。
- 点击卡片可查看完整原文，相关主题句黄色高亮并自动定位。医学资料来源仍可查看完整文件，并在实际提供给模型的参考范围内高亮与问题最相关段落；无法定位时明确提示。
- 「这次不是同一件事」将该来源会话排除在当前聊天之外，排除关系保存在本机。
- 「信息已过时」更新 Mem0 记录的 active 元数据，并回读确认；后续检索再过滤停用记录。
- 「删除记录」实际调用 Mem0 删除接口，并回读确认记录不存在。旧本机记录只从本机删除。失败时不显示成功。
- 纠正会清除相应聊天的服务端上下文（包括图片上下文）；停用/删除会清除该浏览器其他聊天的服务端上下文。已有屏幕回答不会自动改写，再次提问才重新分析。
- 网页不再提供开启/关闭开关；模型在每次聊天中判断人物和保存价值。用户可以通过管理列表编辑、停用或删除已有记录。

## 自动识别本次询问的人物

聊天框已移除「这次在问谁」选择器。网页在调用记忆前，通过当前配置模型判断本人、父亲、母亲、其他亲友、模糊指代、多人或科普问题。模型可识别口语称呼，并用本聊天已确认人物理解连续追问。判定须有用户原话依据、合法类别和足够置信度；解析失败、超时、人物不明或多人时不读取或写入个人长期记忆，回答提示确认。新聊天不继承人物。

回答显示「本次关注：父亲 · 自动识别」等提示。人物改变时，会隔开前一个人的报告图片文字与回答上下文。用户补充「是我爸爸」后可以接续上一轮待确认的症状，不必重述。若用户明确更正「刚才其实是我妈」，开启记忆时会尝试停用刚才存错分组的记录，并将前次原话和本次更正作为可追溯来源保存；失败会显示记忆错误。其他亲友尚不建档，自动识别也不等于人物绝不会判断错误。

新增 `memory/patient_resolver.py`、`memory/test_patient_resolver.py` 和 `verify_patient_resolver.py`。后者实际调用模型测试七组虚构语句，不读写 Mem0；结果在 `verification_patient_resolver.json`。回归运行命令：

```sh

.venv/bin/python verify_patient_resolver.py
```

## 未保存原因与记忆开关（历史版本，已被下述自动判断替代）

自动识别人物只用于确定本次讨论对象，不会自动开启云端记忆。发送时 `remember=false` 的消息不读写 Mem0；回答明确显示「发送时长期记忆处于关闭状态」。输入框旁现可直接查看和切换长期记忆状态，也可从未保存提示中为后续聊天开启。只有用户主动开启/关闭才写入浏览器偏好；刷新后恢复该选择，首次访问、异常偏好或无法访问浏览器存储时仍默认关闭。开启不自动补存之前的消息。

修复了把主题词表当成保存白名单的问题：网页先用人物模型确认个人健康场景，再按开启状态保存；主题词只用于注释与保守检索，不再因词表缺少疾病而丢弃整条原文。增加感冒/伤风/鼻塞等主题别名，使相应记忆可正常关联和高亮。未知人物、多人和通用问题仍不建立个人记录。

新增回归覆盖母亲感冒保存、词表外个人健康描述保存、开关偏好明确选择后的恢复及存储不可用时默认关闭。Python 回归 47 项、来源高亮 6 项、开关偏好 3 项通过。`verify_web_mem0.py` 现在额外写入并核对虚构的母亲感冒记录，检查本人/父亲/母亲三个分组并只清理该独立测试用户生成的记录。

## 亲友折叠栏与记忆编辑

亲友列表改成每人一个默认收起的摘要栏，展开后展示记录和操作。摘要包含总条数、已停用条数及有效记录中最多三个常见主题；主题仅描述历史内容，不推断当前病情。当前支持的亲友分组仍为父亲、母亲。

记录卡片和来源弹窗均提供编辑入口，可修改描述与图片读取文字，不能改人物归属。`POST /api/memories/{id}/edit` 校验用户归属和版本号，通过 Mem0 的 PUT 接口覆盖同一个 ID，然后 GET 回读核对内容与版本，核验成功后才提示保存成功。不新增重复记忆；保留原人物、原记录时间、来源会话和停用状态，更新主题、修改时间与版本。来源会明确标为用户修改后的内容，重新按新内容高亮。摘要及已打开卡片同步更新，服务端旧对话上下文清除，已有回答不会自动重写。

同一进程内按用户和记录串行处理编辑、停用和删除；过期编辑返回 409，失败保留输入供用户处理。版本校验无法替代 Mem0 跨外部客户端的原子条件写入。演示及本机旧记录仅修改本机，不自动迁移或上传。

验证命令增加 `node --test web/test_family_summary.cjs web/test_source_highlights.cjs`。52 项 Python 回归与 12 项前端测试通过。真实 Mem0 验证使用隔离虚构记录，已通过同 ID 更新、回读、条数不增加、过期版本拒绝及原有分组/来源/隔离测试；清理 3 条测试记录，剩余 0 条。网页实际编辑了一条已有的虚构父亲演示记录，来源与高亮正常，条数保持不变。截图为 `.medix-data/family-bars.jpg`、`.medix-data/memory-edit.jpg` 和 `.medix-data/memory-edited-source.jpg`。


## 模型自动判断长期记忆（当前网页行为）

按用户要求移除侧边栏及输入框的记忆开关和浏览器偏好逻辑。输入框显示「智能长期记忆 · 自动判断」。网页 `/api/chat` 不再接受旧开关控制行为，旧页面携带的 `remember=false` 也不会关闭自动判断；人物同样统一交给模型判定。旧消息不补存，原有记忆及管理功能保留。

人物识别的同一次模型调用额外输出 `should_store`、`memory_evidence` 和 `memory_reason`。仅对明确的本人/父亲/母亲、模型建议保存且有可核对用户原话的信息写入 Mem0。症状变化、病史、用药、过敏、检查结果可保存；闲聊、科普、假设、无新增事实的纯建议追问，以及用户明确要求不保存的本次信息跳过。确认或更正人物时可引用前文用户事实，助手输出不能作为事实依据。相关历史的检索与是否新增记录分开，因此追问仍可参考历史但不重复保存本轮。

结构化结果缺失、截断或超时时保守跳过，并提示自动判断未完成；不将该失败当成模型正常拒绝保存。当前模型结构化输出预算为 2048 tokens、超时 40 秒，以容纳联合判断。模型决策不保证永远正确，用户可查看保存原文并编辑或删除。

自动测试：`.venv/bin/python -m unittest memory.test_patient_resolver memory.test_case_memory memory.test_web_mem0 web.test_web`、`node --test web/test_family_summary.cjs web/test_source_highlights.cjs`。真实模型策略验证：`.venv/bin/python verify_memory_policy.py`，使用六组虚构语句且不写入 Mem0，结果写入 `verification_memory_policy.json`。


本轮验证结果：55 项 Python 回归、9 项前端测试、6 组真实模型自动存储判断均通过。真实模型覆盖母亲健康事实保存、寒暄不保存、科普不保存、假设不保存、无新增事实的建议追问不保存、明确要求不保存。网页实际聊天使用虚构的妈妈鼻塞/咳嗽描述，自动识别母亲并写入 Mem0，经列表回读确认母亲分组 0→1 条；随后发送周末看电影的普通闲聊，显示不保存且回读仍为 1 条。来源卡片与高亮、亲友折叠分组、编辑覆盖同 ID 的功能均保留。

## 编辑后的同聊天召回

修复了「保存 39 度 → 编辑为 38 度 → 在同一聊天追问」无法召回的问题。旧检索逻辑排除了来源会话等于当前会话的记录，而编辑又清除了旧对话上下文，导致修改后的唯一有效来源也被排除。现在本机与 Mem0 记录均允许同一聊天召回，同时保留用户/人物隔离、停用、删除和主动排除限制。

Mem0 搜索结果只用来发现候选 ID；进入模型上下文前，按 ID 回读当前记录，重新检查人物、有效状态及主题，避免搜索缓存中的旧值覆盖用户编辑。若语义索引尚未命中，则从同一用户、同一人物的有效记录中找相同健康主题，再按 ID 回读；不向其他人物或停用记录扩展。新增「体温」主题别名，支持「体温是多少」的表达。修改后的来源会显示「参考你修改后的记忆」，并保留来源卡片、高亮和修改时间。

仅核对既往事实时，提示模型直接回答来源中的当前值，保留引用，不机械展开医疗建议模板。本轮追问是否新增记忆仍由模型判断，正常的事实追问不会另存一条同内容记录。

回归覆盖同聊天本机召回、Mem0 搜索缓存仍是 39 度但按 ID 回读为 38 度、搜索未命中时回读恢复、体温别名，以及停用/删除/排除与跨人物/用户隔离。真实链路验证脚本为 `.venv/bin/python verify_edited_recall.py --base-url http://127.0.0.1:8767`：使用随机隔离的虚构测试用户，经正式聊天、编辑和查询接口验证同聊天与新聊天的回答及引用，最后清理该测试用户的记录；结果写入 `verification_edited_recall.json`。


本轮结果：62 项 Python 回归、9 项前端测试通过。真实 Mem0/模型验证已通过同 ID 编辑、同聊天回答 38 度并引用修改后的记录、新聊天回答 38 度并引用修改后的记录，以及两次追问均不另存记录；测试用户生成的 1 条记忆已删除，剩余 0 条。测试服务验证后停止，用户需重启自己正在运行的服务以加载修改。

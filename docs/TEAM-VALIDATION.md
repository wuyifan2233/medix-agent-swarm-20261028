## 2. 现在统一采用的方案

- 登录统一为手机号账号：注册验证短信并设置密码；登录支持手机号＋密码、手机号＋验证码。注册成功后自动登录。密码登录不发送短信。
- 全部私有业务以服务端 `user.id` 为归属键；昵称、手机号、浏览器Cookie和模型输出不能代替它。修改手机号或密码不会生成新的用户ID。
- **每台电脑一份业务SQLite**，默认 `.medix-data/app.db`；账号、档案、偏好、病例、记忆、提醒、渠道绑定、聊天历史与关怀点账本进入同一业务库，迁移至20261031_17。启动自动建库/升级，无需启动MySQL、Redis或Qdrant服务。
- 公共医学资料可以共享；私人档案、病例、记忆、提醒必须隔离。向量索引仍独立用于检索，Mem0仍是可选云服务，它们不各自再维护一套登录账号。
- 微信/QQ是消息和提醒渠道，不是网页第三方登录。先登录MediX账号，再连接渠道；本机每个渠道只供一个MediX账号连接。
- **Git只同步代码和说明，不同步本机账号、数据库、密钥、模型缓存或知识库正文。** 同一手机号在不同电脑上的本地库中也不会自动共享资料。

## 3. 明天怎么拉取和启动

推荐在新目录验证，保留自己的原功能工作区。本机已验环境是Windows、64位Python 3.10；其他环境请记录实际版本和安装问题。

```powershell
git clone --branch main_copy --single-branch https://github.com/wuyifan2233/medix-agent-swarm-20261028.git medix-integration
cd medix-integration
python --version
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.integration.txt
Copy-Item .env.example .env.local
```

如果已有干净的main_copy工作区，使用 `git pull --ff-only origin main_copy` 更新。不要用重置或覆盖文件的方式处理自己未提交的开发内容；已有 `.env.local` 不要重新覆盖。

先填写本地配置，再启动：

```powershell
.\.venv\Scripts\python.exe run_web.py
```

浏览器访问 `http://127.0.0.1:8765/`。不要直接打开 `web/static/index.html`。已有8765实例时，可使用 `run_web.py --port 8767`；如还要隔离业务数据，可加 `--data-dir .medix-data/preview`。

新目录没有原来的账号。先配置短信并完成真实注册；仓库不提供公共测试密码。自动化测试生成的合成账号仅用于回归，不能作为短信发送验收。

### 必须知道的配置

在 `.env.local` 填写；短信凭据也可单独放 `.env.sms`。更改后重启服务。它们均已被Git忽略。

| 配置 | 用途 |
|---|---|
| MEDIX_IDENTITY_NAMESPACE | 每位同学设置不同且稳定的值，如 dev-member-a；共用Mem0时也要区分环境 |
| MEDIX_LLM_PROVIDER、DEEPSEEK_API_KEY等 | 使用现有DeepSeek配置时填写真实密钥 |
| MEDIX_LLM_PROVIDER=auto、OPENAI_API_KEY、OPENAI_BASE_URL、OPENAI_MODEL | 使用兼容接口时填写模型负责人确认的地址、模型名与密钥；将样例中的deepseek选择改为auto |
| MEM0_API_KEY | 真实跨会话长期记忆需要；仅体验虚构演示不需要 |
| MEDIX_SMS_ACCESS_KEY_ID、MEDIX_SMS_ACCESS_KEY_SECRET、MEDIX_SMS_SIGN_NAME、MEDIX_SMS_TEMPLATE_CODE | 注册、验证码登录、找回密码等；由短信负责人确认权限、测试号码范围和额度 |
| MEDIX_KB_BACKEND=milvus | 验收原有向量RAG时建议使用严格模式；auto可能转为标注“文本后备”的检索 |

模型必须支持所测能力：**文本回答成功不等于支持图片输入和工具调用。** 病例负责人需确认图像模型；提醒负责人需确认工具调用。不能把占位符xxx当作有效密钥。

短信配置见 [SMS-SETUP.md](SMS-SETUP.md)。真实密钥由负责人通过合适的私下渠道配置，不写进代码、Issue或验收反馈。

## 5. 各负责人按什么步骤验收

全部使用虚构健康资料。结果填“通过 / 失败 / 未验证（缺什么）”，不要只看页面能否打开。

| 模块 | 操作与通过标准 | 额外依赖 |
|---|---|---|
| 登录权限 | 新注册后自动登录；退出后分别用密码、验证码登录；密码登录不发短信；刷新后账号正确；另验头像、昵称、找回密码和修改手机号后的资料保留 | 真实短信；后台还需管理员账号 |
| 健康档案 | 「我的健康档案」填写虚构资料并保存确认，刷新能读回；当前问题勾选授权后才使用本人档案，不勾选不携带；账号B不能看到A档案 | 保存不依赖模型；回答使用需模型 |
| 个性化 | 「回答偏好」切换语气、简短/详细等，保存刷新仍保留；实际回答随偏好变化；不能把偏好推断成医学事实 | 实际回答需模型 |
| RAG/知识库 | 普通入口验证旧库召回；证据入口搜索“高血压饮食”，核对来源分类、目录分页、原文和引用；无匹配时不能编造来源 | 本地模型/索引；生成回答另需问答模型 |
| 病例分析 | 点击首页「试用图片示例」并发送，核对虚构图片里的三次记录；继续追问刚才数值；新会话通过「接着哪个病例聊」选择；明确更正后不能继续引用旧值 | 支持图像输入的模型 |
| 长短期记忆 | 先用「体验记忆新功能」验证虚构演示；真实模式描述虚构情况，检查是否写入，再开新对话追问；父亲/母亲与本人不能混用；编辑/删除后核对结果 | 真实模式需问答模型和Mem0 |
| 提醒 | 提问“请在两分钟后提醒我服用维生素C”，核对实际返回时间、侧栏任务、到点提醒；再验取消、重启恢复和不能取消别人任务；含糊时间应追问 | 对话创建需工具调用模型；到点调度需网页服务保持运行 |
| 微信/QQ | 「聊天渠道与提醒」中连接；微信扫码确认，QQ好友回复绑定码；从手机发消息并收到对应回答，再测定时推送；其他MediX账号不能接管连接 | 微信接口/本机QQ、SnowLuma/OneBot环境；智能回答另需模型 |

记忆验证注意：当前集成在使用本人档案、回答偏好或病例事实上下文时会暂停云端记忆路径。先关闭本轮档案授权、关闭回答偏好并不挂接病例，单独验证真实记忆；再把组合场景交给相关负责人联调。虚构演示成功不等于真实Mem0写入成功。

QQ负责人需准备本机客户端环境；必要配置包括 `MEDIX_SNOWLUMA_HOME`、`MEDIX_QQ_EXE`，或已有OneBot的 `MEDIX_QQ_HTTP`、`MEDIX_QQ_WS`、`MEDIX_QQ_TOKEN`。不要在未确认绑定的情况下给他人发送测试内容。

管理员验证需先把本机已注册账号设为管理员。现有工具是 `scripts/set_admin.py --phone`，应指向当前验收使用的业务库；设置后重新登录。不要用旧的用户名创建管理员脚本作为手机号登录验证。

## 6. 所有人都要做的双账号检查

准备测试账号A、B；同时开两份会话时使用普通窗口与无痕窗口，避免同一浏览器共用登录Cookie。

1. A保存一份明确标记为“A专属测试”的档案、病例、记忆或提醒。
2. 登录B，不能看到、改动、删除A的数据；公共医学资料仍可共享。
3. 再登录A，原来的数据仍在。
4. 修改A的手机号或密码后，仍回到同一账号，不能丢资料。用专门测试账号验证，不必注销日常账号。

检查实际检索结果/模型上下文的归属，不能只以回答碰巧没提到别人的资料作为通过依据。

## 7. 出问题先按这个顺序定位

| 现象 | 先检查 |
|---|---|
| 短信提示未配置 | 本机.env.sms字段、启动入口、配置后是否重启；其他电脑不会自动拥有演示机的密钥 |
| 手机号尚未注册 | 本机业务库是否新建；先注册，验证码登录不会自动注册 |
| 等待60秒 | 同一手机号的发送冷却；不要连点重发 |
| 模型未配置、401、403 | 密钥/提供商地址/模型名；不要为排查模型问题清空数据库 |
| 记忆不能打开或无真实记忆 | Mem0配置和调用结果、是否在虚构演示模式、是否被档案/偏好/病例上下文暂停 |
| 180条已就绪但证据目录不可用 | 正在用普通旧库入口；证据功能按第4节准备并启动 |
| 知识库锁定或端口占用 | 先停止旧实例；向量索引不能让多个进程同时占用；换端口必要时配独立索引 |
| QQ/微信无法连接 | 客户端、桥接和网络配置；二维码能显示不代表消息收发已通过 |
| 403安全校验失败 | 从正确的本地地址访问；端口与MEDIX_ALLOWED_ORIGINS是否匹配；前端写请求是否经MedixAuth并携带JSON和CSRF |

离线回归可运行：`.\.venv\Scripts\python.exe scripts/verify_integration.py`。它使用合成账号和模拟外部服务，不会证明真实短信、模型、Mem0或机器人可用。

## 追加验收：会话、流式与关怀点

交付细节见 [CHAT-DELIVERY.md](CHAT-DELIVERY.md)。使用两个虚构账号验证：

1. 完成一轮问答，刷新或重新登录后恢复会话；新建、切换、重命名、删除均只影响当前账号。
2. 观察流式正文、停止生成和刷新后恢复；取消产生的未知用量显示待核对，不能当作零消耗。
3. 左下角查看关怀点余额和消耗记录，重新启动不重复赠送；网页与已绑定QQ/微信共用该账号额度。
4. 充值目前仅创建、取消或过期未支付订单，不提供真实付款与到账，创建订单不会增加余额。
5. 检查另一账号不能读取或操作这些会话、用量、账本与订单；修改手机号仍保留原user.id和数据。

默认新钱包赠送10,000关怀点，收费模型须具备人民币费率配置；按请求用量参考估算，不能等同供应商最终账单。

## 追加验收：跨模块语义路由

- 身份与记忆：问「我是谁」「还记得我说过什么」，应只依据当前账号的昵称、允许的聊天/档案/记忆回答；没有资料明确说不知道，不返回公共医学库不足。
- 普通交流与提醒：不要求医学证据；查询或创建提醒仍经当前账号绑定的工具，不因库里没有该句而拦截。
- 医学问题：问疾病、症状或药物安全仍检索医学资料；未命中本地资料时可给明确标记的一般健康信息，但不得伪造引用、给出个人剂量或确诊；needs_information仍追问关键信息。带问候的医学问题仍属于医学请求。
- 报告与追问：上传或核对已有报告事实，不因公共库缺少该报告就拒绝读取；诊疗结论仍需相应依据。
- 连续追问：区分「那怎么处理」延续医学主题与「我是谁」明确换主题；不得跨账号继承上下文。

## 追加验收：语音输入和朗读

先安装更新后的requirements.integration.txt（新增edge-tts==7.3.1），沿用统一启动入口，无新增业务库迁移。语音说明见[VOICE.md](VOICE.md)。

1. Chrome中点击语音输入，按浏览器提示自行授权麦克风；说完后核对、编辑文字，再自行发送。SpeechRecognition由浏览器提供，不承诺离线；服务端ASR为可选独立MEDIX_AUDIO_*配置，不能用DeepSeek文字Key代替。
2. 回答下点击朗读/停止，验证边接收边播放。Edge TTS无需Key但需要联网，正文会发送微软云端，不落盘用户音频。自动朗读由每个账号显式开启，恢复历史不自动重播。
3. 个性化声音中试听固定短句、保存音色，切换账号不继承对方设置，关闭或停止应取消播放。音色复用当前账号偏好表，无额外数据库。

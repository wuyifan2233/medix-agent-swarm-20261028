# 自然聊天式病例记忆（本地版）

用户直接上传报告或描述情况，后台提取事实，正常回答；没有字段表、强制校对或确认按钮。图片不清晰、修改对象不唯一时，只针对关键疑点自然追问。模型提取和解释仍可能出错。

## 使用

- 新对话默认不关联旧病例。输入实际病例事实后自动建立本机病例；一般健康知识问题不应当作患者病史保存。
- 同一轮说“刚才读错了，正确值是……”会修订指定记录，“那次是餐后测的”补充条件，“今天新测……”新增测量。
- 新开对话或刷新后，在侧栏“接着哪个病例聊”选择旧病例。该选择只关联病例事实，不恢复完整聊天。
- 不同患者请开启新对话。后台检测到明确换人描述时也会切换病例；此识别依赖模型，必要时请明确说明。
- 回复会提示本轮新增／更新，并提供可折叠的“本次结合的病例资料”。旧回复引用的字段被修改后，页面标注“信息已更新”。

## 保存与索引

- `web/case_memory.py`：默认项目下 `data/case_memory.sqlite3`（`MEDIX_CASE_DB_PATH` 可覆盖），保存当前事实、不可变修订版本、来源片段、请求幂等记录及带版本引用的分析。不是完整聊天存档，不保存原图。
- `web/case_context.py`：用统一 `LLMClient` 输出后台变更提案；代码校验来源原文、修改对象、病例归属和版本。更正值需要出现在用户原文中，补充操作不能覆盖数值。
- 单位、参考范围、检测方法和测量条件若无法在原文中找到则留空；检查日期仅接收明确日期或可解析的“今天／昨天”，不以上传日补齐缺失日期。
- Milvus 使用独立集合 `medix_case_facts_v1`，与 `medical_knowledge` 分开。稳定记录 ID 的 upsert 替代旧索引内容；检索同时按浏览器 owner、病例 ID 过滤，并用 SQLite 再核验版本。
- SQLite 与 Milvus 不是跨库事务。SQLite 先提交，dirty 标记记录待同步；索引失败时使用 SQLite 当前事实，不引用过期向量。后续相关请求重试同步，集合缺失时重建。
- 同一请求重试复用 request_id，防止病例重复写入。新增测量与修正旧值分别建新记录／修订版本。

## 依据与趋势

SQLite 按每页200条读取当前病例全部有效事实；向量索引按128条分批核对及更新，不再静默丢弃160条以前的记录。提案按本轮项目、日期从全部事实中筛选最多80条候选，因此较早记录也可进入更正范围。候选仍无法唯一定位时自然追问，不猜测修改对象。

回答优先使用本轮变更、按项目和日期检索的事实、语义检索结果，并补充同项目的历史日期记录；为限制提示长度最多选160条。没有选入全部记录时明确提示资料范围。索引失败时按项目和日期在SQLite记录中筛选，页面和模型输入同时提示语义检索降级，不使用旧向量值。

图片逐张输出项目、结果列、单位、参考范围和原文行。代码检查结果是否为该行的结果列，拒绝把参考上下限当作结果；这仍然依赖视觉模型正确转录原文，并非独立OCR的准确性保证。输出截断、格式异常、行数不符或校验失败时，最多分四个重叠区域补读一次；仍不完整时展示提示。图片清单每24项分批提取病例变更，遗漏项补提取一次，并核对与实际保存记录是否匹配。单次最多2000项操作；原图不保存，补读仅在请求内存中进行。

清单与入库对账只能检测可观测的遗漏，不能证明原图没有任何漏读。非表格正文没有逐段完整性保证。模型服务须支持图像输入与JSON输出；分区补读增加调用次数和延迟，仍受整次请求超时限制。

只有同名项目、日期先后明确、单位／方法／参考范围／测量条件一致且均为明确数值时计算差值。缺少条件时仅并列描述；修订版本不是新的测量，不计算成病情变化。差值不等于整体健康好转，单据参考范围不等于疾病诊断。

分析只注入当前版本事实，不沿用旧图片读取和助手回复作为证据。普通聊天上下文与病例事实分开；有病例时禁用 Mem0，避免旧摘要重新引入已更正值。模型是否准确理解纠错、是否遵守解释边界仍需评估，不构成临床验证。

## 本地版边界

SQLite 明文保存，病例向量位于当前 Milvus 数据目录；`data/` 和运行时向量库不进入源码交付。医学知识库仍保留项目附带的180条索引。

浏览器一年有效的 HttpOnly Cookie 用于本机档案隔离，没有登录、跨设备同步、加密或自动备份。清除Cookie后旧记录仍在磁盘，但当前界面不能找回归属。本地不同浏览器不共享患者记录，不是公网身份认证方案。

上传图片、当前问题、选出的病例事实及医学检索片段会发送到配置的模型API。后台结构化提取按批次调用模型，遗漏重试与分区读取会产生额外调用。病例数据不会通过本流程写入公共医学知识集合或Mem0。

离线测试：`python -m unittest web.test_case_pipeline web.test_case_memory web.test_web tests.test_deepseek_config`，全部使用合成数据／临时SQLite／模拟模型和索引。新增测试覆盖250条历史、旧记录更正、结果列与参考值混淆、55项分批入库、遗漏重试、不同图片日期隔离和接口降级提示。真实模型和Milvus联调应另用虚构病例检查。

此前27项回归覆盖图片Markdown／标点格式容错及跨行参考范围拒绝；此前DeepSeek和实际Milvus联调验证了首次记录、旧值修订、新增测量、跨会话引用和浏览器隔离。本次升级另以临时真实Milvus库和合成向量验证了250条记录全部索引及较早记录检索，尚未重新进行真实视觉模型端到端验证。这些检查不是医学有效性评估。
